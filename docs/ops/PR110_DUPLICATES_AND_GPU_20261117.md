# PR110：重复动作没有消除后续计算，以及 GPU 等待问题

证据时点：2026-11-17 15:27–15:28 CST。本文补充 [D3 执行进展](PR109_D3_REFIT_PROGRESS_20261117.md)，记录已确认的问题、原因与待实施改进；不是优化已经上线或提速已经成立的声明。本次仅上传说明与已有运行证据，未修改作业、奖励或搜索预算。

## 1. 动作重复为什么还在展开？

**目前只合并了树边记录与部分训练计算，没有合并成功后继的执行和完整后续推理。** 原实现覆盖了语义去重和失败缓存，却没有完成计算结果复用。这是当前实现缺口，不能把它描述成已经实现了完整节点合并。

| 位置 | 当前行为 | 是否节省模型后续推理 |
|---|---|---|
| 同一精确父状态下抽中相同语义动作 | `DecisionNode.add` 追加真实 `receipt_id`，增加重复次数，沿用原边 | 不自动节省 |
| 已知失败的重复动作 | 新动作仍由模型生成；缓存拒绝后跳过 Executor | 只节省重复执行，不节省已发生的生成 |
| 已接受的重复动作 | 仍执行并生成后续；没有 accepted-successor 缓存或共享在途任务 | 没有节省完整 suffix |
| 分支 Q | M=1 只使用每个语义动作首个声明的完整后续；重复抽样不增加 baseline 票 | 不回收已经发生的推理成本 |
| 训练回执 | 共享前缀只进入 loss 一次；相同训练序列前向可合并 | 主要节省学习端计算 |

实际顺序是：模型完成一次动作生成 → `ObservedEpisode.accept` 执行 → 收集器 `_completed` 才把动作加入语义边。即使 `add` 发现重复，也只是更新边记录，没有将这个 episode 接到已存在的后续计算上。重复次数上限限制父节点再抽样，但不终止已启动、已接受的重复后续，也不消除其他深度处的新节点分叉。

此外，精确节点身份包含 `tree_id`、完整 prompt token IDs、工具、已接受历史、反应 occurrence、路线待办和行为策略版本。不同 G4 初始树之间，即使某个化学结构相同，也不会自动合并。化学结构一样、输入历史不同，不等于同一个策略条件。

### 为什么不能简单把一整条旧随机后续复制过来？

同一精确状态、同一动作的确定性 Executor 结果可以复用。后面的策略动作是随机采样：相同第一个动作不意味着后续路线一定相同。当前 M=1 信用定义与“完整搜索探索更多后续”还混在同一个收集器里，额外重复后续可能继续寻找路线，却未必提供一个新的分支 Q 样本。

需要把这两个目标显式分开。共享状态、边和已完成价值，不代表把旧动作 token/log-prob 复制成新的真实抽样；同一真实回执也不能因为多条路径引用而重复加入梯度。重复次数可用于搜索统计，但不能直接成为额外奖励或给语义 baseline 增加票数。

本次没有扫描全部轨迹来量化重复动作比例，也没有测得“合并后可节省多少秒”；不能从 3,300 条报告直接推断有多少是等价重复。

## 4. PR110 尚未解决的问题与验收要求

以下均为待实施项，没有改变 PR109 的已冻结算法、采样概率或当前运行合同：

1. **先明确重复边的计算所有权。** 精确条件/动作下，复用确定性执行结果；增加在途结果登记，使多个订阅者等待同一次执行。原始真实采样回执分别保留。成功后继的输入完全一致时才能共享后续工作。
2. **分开 M=1 训练取值和额外搜索探索。** 已声明的首个后续 Q 完成后，重复动作是否还需要新完整后续，应成为显式预算/统计口径。若采用直接复用/提前停分支，必须定义共享回报、删失和梯度权重；不能把缓存随机路线伪造为独立新样本，也不能在未论证前直接复用 Q 给所有 G4 路径。
3. **统一同一行为策略版本的推理派发。** 将 episode 的化学状态/奖励归属与执行 GPU 分离，使空闲 GPU 处理慢分片的已就绪模型请求。共享 prompt、真实 token/log-prob、请求 RNG 和回执归属必须正确；整批采样完成前不提前更新 actor 引入策略版本漂移。
4. **接通有概率核验的连续推理后端与前缀复用。** vLLM 代码存在不等于运行可用；沿用相同 actor、输入、工具和概率验收，不能为通过而放宽核验阈值。替换框架也不能代替解决固定分卡和重复后续的问题。
5. **学习端按长度/容量组织批次。** 在内存与损失/梯度等价核验后扩大微批次或做兼容的序列组织，保持每个真实回执一次、固定归一与分支信用。不能仅修改配置就宣称已测得加速。
6. **同时报告有效工作和等待。** 保留实际模型请求数，新增独特状态/边、重复提案、确定性执行缓存命中、共享在途任务、实际新增后续、用于 Q 的样本数、各卡等待与阶段耗时。分别比较物理调用成本和学习信号，不用 token 总量代替这些指标。

完成条件是同一协议、同一输入与统计范围下，实际决策/重复执行/等待时间下降，回执、奖励、概率和梯度语义正确；不是只看到 GPU-util 上升。当前无这些改进的实测提速结果。
