## Runtime changes

`route_failure_policy.py` versions the opt-in contract. In the native episode,
the first non-resource rejected action ends that **sampled rollout**. The
Executor-owned state is not changed. `RefitCollection` keeps an independent
copy of its pre-action parent, and samples a fresh sibling from precisely the
same observation. It does not append a failure-repair conversation to that
episode. Legacy contracts and running frozen code remain unchanged.

The parent is OPEN_WITH_REJECTIONS, not globally failed. Rejected edges have
no artificial child. A known rejected semantic draw retains its new generated
tokens and actual behavior log probabilities, but skips a repeated Executor
call. Parent exhaustion requires its declared expansion/duplicate ceiling.
Resource outcomes stay censored and do not chemically exhaust the parent.
The new FINISH guard also requires a genuinely state-changing accepted FLOW
in the current reaction occurrence; net principal endpoint change and cycle
guards still apply. Charged products alone do not establish premature FINISH.

`route_flow_credit.py` conservatively attributes already verified reference
progress to unique persistent mapped graph edits. Cancellation, inventory
changes, repeated edits or ambiguous mapping fall back to FINISH. This is
bookkeeping evidence, not proof of physical mechanistic causality.

For L reference steps, q=.2*min(unique trusted reference edges/max(L,1),1),
C=1-exp(-E/4), eta=.05/max(L,1). Ordinary rejection adds1 to E, route cycle2,
and semantic repetition adds1 extra. Event reward is

```
r_t = delta(q_t) - eta*delta(C_t) + 1_terminal*(B-q_t)
```

On a failed rollout B=0, so its terminal event rolls back previously earned q.
The total becomes -eta*C. Earlier accepted chemistry is retained as evidence;
only the failed edge adds a new failure cost. C/D shift alpha=.5 of a verified
FINISH increment onto attributable FLOW records, exactly conserving total
return. Alpha0 is the unchanged timing fallback. There is no accepted-FLOW
count bonus, new critic, learned reward model or external teacher.

`route_refit.py` binds nodes to exact prompt IDs, tool schema, mapped state,
accepted history, occurrence, route obligations, behavior version and Executor
contract, within the original target tree. Canonical SMILES alone never merges
nodes. Forks keep canonical occurrence IDs while genuine new draws receive new
request IDs. Runtime cloning shares the immutable stock, avoiding a copy of
255,435 inventory entries per decision. Durable recovery replays original
receipts and reconstructs the same forks and identities.

The first runtime uses original full-policy sampling, M=1, max8 decision nodes
per independent tree,2 distinct expansions per node,2 duplicate draws and16
additional suffix forks per tree. These limits bound extra search, not chemical
episode length or resource failures. It never forces FLOW or uniqueness.
Different semantic FLOW choices at the same exact node get

```
Q_j = matched suffix return (including failed terminal rollback)
A_branch_j = Q_j - mean_over_distinct_semantic_actions(Q)
```

Duplicate draws do not receive another baseline vote. Any incomplete, resource
or unknown-proposal member masks the entire conditional node. Branch advantage
**replaces** the independent G4 advantage for its root action. Other original
G4 actions keep their valid original advantage; extra suffix actions without an
eligible conditional comparison are masked. Shared prefix receipts enter loss
once. The existing clipped token loss, actual behavior denominator, fixed
reference KL and C1024 normalization remain. The unique-receipt implementation
has an independent dense-gradient test.

Both rolling HF batches and asynchronous vLLM collectors support dynamic suffix
episodes and CPU execution. The formal initial configuration keeps the already
validated HF backend. This work does not assert a new vLLM numerical parity
result or measured throughput gain. Actual model requests/Executor calls are
counted by unique receipt ID; shared-prefix path copies are not new inference.

## Final review and focused verification

An independent read-only whole-branch review found two Important scheduler
defects before launch: pending ancestor forks could reuse request IDs, and two
workers could retain nodes past the frozen node ceiling. Both were reproduced
with real CPU Executor calls and locked by failing regression tests before the
fix. The controller now reserves outstanding expansion/duplicate slots,
allocates monotonically increasing per-node draw serials, releases reservations
at the first completed fork action, and rechecks node capacity during serialized
harvest. Journal-only replay reconstructs those same reservations. Pending slots
do not declare a chemically exhausted parent. The asynchronous path also flushes
the execution prefix before dispatching derived requests; HF already flushes
before generation. This closes the durable-recovery boundary without a chemical
failure label for storage faults.

The complete focused collection passed214 tests. After the final durability
addition, all67 affected scheduler/optimizer/training/validation/distillation
integration tests passed. The suite includes both rolling and asynchronous
ReFIT collection, real CPU chemistry, journal-only restoration, original native
tokenizer observations and independent dense gradients. These counts overlap;
they are not added together. No full-project CI or model/benchmark result is
claimed. Candidate01 passed static provenance but is explicitly DO_NOT_SUBMIT;
the fixed code requires a fresh02 snapshot and contract. No deferred Minor
review findings were reported.
