# 第三阶段：多步逆电子流优化、GT 监督与机理模板

状态：讨论稿，未实现、未提交训练。本文不替换现行 EARHO，不修改正在运行的训练或 MCTS。

## 目标与范围

让端点是否正确的信号作用于连续的电子决策，而不是只优化首个动作。保留两阶段 SFT 的输入、真实执行状态反馈和压缩历史，不新增 backbone、图网络或独立 value model。

本稿的“多步”指**同一次反应内的多步逆电子事件**。STOP 结束这次反应，不等于整条合成路线已经到达购买库。跨反应的路线级 RL 另行讨论；R1/R2 的现有 MCTS 也不因此改变。

用户要求是兼顾 GT 监督和高可信模板；下文的具体损失、起点混合方式和工程安排是实现提议，不是已验证有效的结果。

## 与当前实现的区别

现行实现依据 [PR #97](https://github.com/wangyu-sd/MechET/pull/97) 中的 `scripts/train_pr96_earho.py`，入口提交 `5c7cb9617663df01022b464e2eb4873fe30042a4`。采集和更新分别在 `collect()`、`optimize()`。

| 项目 | 当前实现 | 本稿提议 |
|---|---|---|
| 采样 | 两个首动作，之后 greedy continuation | 同一初始上下文的多个完整、独立采样后缀 |
| 展望 | 局部 horizon；另有从根开始的长回放 | 继续到真实 STOP，不以 H=2 作为学习终点 |
| 策略更新 | 只更新采样首动作 | 更新后缀内所有模型生成动作，包括 IMPORT、FLOW、STOP |
| GT | 无有效支持时回放一个参考动作 | 独立的 GT 多步轨迹监督项，与在线 RL 分开记账 |
| 模板 | 尚无本稿提出的过程项 | 冻结原作者模板，检查逆事件的正向对应转移 |

当前支持更大 horizon 的配置，不代表历史运行已经进行了整轨迹策略更新。新方案也不能只改 horizon 数字就声称完成。

## 方案取舍

1. **只加长原 EARHO 的展望**：改动小，但仍只更新首动作，不能回答本次希望优化连续决策的问题。
2. **完整采样后缀 RL + 独立 GT 监督 + 模板辅助项（建议）**：端点回报能够直接更新整条生成路径，保留已有工具协议；代价是采样更长、端点回报仍稀疏。
3. **只收集成功轨迹再 SFT**：训练简单，但不是在线策略优化，也不能冒充第三阶段 RL。本稿不以此替换方案 2。

## 训练流程

每个训练反应有一个公开主产物起点、参考轨迹和参考前体。训练起点混合两类：

- **产物根起点**：仅给主产物，模型自主完成整个反应；这是端到端能力的直接训练条件。
- **GT 前缀起点**：执行一段 TRAIN GT 前缀，得到当前真实状态及同协议的压缩历史；模型自主完成剩余后缀。提示中不给未来 GT 动作、GT 前体或“还剩几步”。

GT 前缀必须按真实动作执行，不能直接拼接一个状态字符串。每个起点下独立采样多条后缀，模型参数在本轮采集期间冻结。所有后续动作都由同一行为策略采样，不再把 greedy continuation 当作随机策略样本来更新。

IMPORT 仍穿插在电子流中，用到时引入；不先列全环境清单。模型通过原有工具参数生成片段和电子事件，不改成选择 GT 候选或模板 ID。

起点混合比例依据 **TRAIN 根起点的完整端点表现**调整，并记录每轮实际比例；不能因后缀容易成功就取消根起点。VALID 不参与梯度或训练起点挖掘，TEST 不参与调参、回放或模板构造。

## 三种信号怎样组合

### 1. 端点 RL 是主目标

只有模型正常 STOP 且通过原执行协议，才比较最终结构前体集合与 GT。去掉 atom map、忽略组分排列，但保留立体、同位素、电荷与必要的氢信息；沿用结构前体/完整混合物分开的评分口径，不临时改变标签定义。

端点命中记 1，已终止但不命中记 0。合法但不同于记录的前体只是“不命中 GT”，不能直接称为化学错误。GT 只用于停止后的评分，不用于偷偷提前终止或选取轨迹中最接近答案的状态。

采用 actor-only 的组相对 clipped policy objective；同一起点的一组**真实策略样本**提供相对回报基线。端点优势作用于所有生成动作的 token，工具返回值、系统提示和输入状态全部 mask。固定原 Stage-II 参考策略做 KL 约束，不增加可训练 critic。

组内端点回报全部相同时，该组没有端点相对优势，必须如实记录；不能注入 GT 候选、伪造成功样本或把 CE 梯度算成 RL 梯度。对动作/token 的汇总、跨反应归一化和 KL 估计须在实现计划中明确，避免长轨迹仅因 token 多而被过度加权。

### 2. GT 作为独立监督锚点

保留 TRAIN 的完整参考轨迹或连续参考后缀，使用与 Stage-II 相同的状态/历史渲染，预测每个参考动作。概念上的总损失为：

`L = L_endpoint_policy + beta * L_reference_KL + lambda * L_GT + eta * L_template`

这里各项系数尚未冻结；GT 项是显式的 assistant-only CE，不是伪装成 on-policy rollout 的参考答案。即使策略组全部失败，GT 项仍可提供梯度，但日志必须分开报告 RL、GT、模板各自的有效样本数和更新贡献。

多个对称等价绑定、不同动作序列可得到同一端点，不要求采样路径逐字复刻 GT。GT 动作不一致本身不是负奖励理由。

### 3. 高可信模板是辅助过程证据

首选已经审计的 **FlowER 原作者机理模板**，不是通用逆合成净编辑模板。现有审计见 [PR #90](https://github.com/wangyu-sd/MechET/pull/90)；作者源为 [Mechanistic_dataset](https://github.com/jfjoung/Mechanistic_dataset/tree/8bd5b38e9602c4d45485bf50076d03c292dcc486)。

模板对逆事件 `s -> s'` 检查其正向对应 `s' -> s`。必须保留完整状态、映射对应、电荷/自由基/氢变化及适用前提，不能只匹配局部 SMARTS 就宣布机理成立。模板版本和单规则/组合规则证据分开记录；mech-31k 的适用性不能由 FlowER 的历史覆盖率代替。

过程项的精确形式保留为本 PR 的讨论点：优先考虑小权重、有界的兼容性辅助项，而不是模板硬筛选动作。匹配、未支持、明确矛盾、检查资源不足应分开；未匹配不是化学负例。缺少条件信息时，只能声称结构转移兼容，不能声称该条件下反应已被证实。

不得按模板匹配次数无限累加奖励；重复事件、无状态变化和循环不能刷分。模板项不能代替端点目标，也不能让“不断 IMPORT、不 STOP”成为高分路径。IMPORT 本身不因任意新增分子而获奖；后续参与电子流的模板证据也不等于整个环境混合物相容。

带电端点不自动判错。不得为了命中购买库而免费中和离子；质子转移、活化或盐形式转换需要明确的事件/规则依据，并与严格原始评分分开。

## 效率与证据保存

- 使用跨反应滚动 batch，完成一个动作即可把下一状态重新入队；避免等整组最长路径结束才补入新请求。
- 将采样与 CPU 执行/模板检查流水化。模板检查结果按完整状态对、方向及目录版本缓存；策略样本必须绑定行为权重版本，不能跨更新复用为新鲜 on-policy 数据。
- 共享上下文可以复用编码/KV，但不同历史、不同私有状态不能只凭相同 SMILES 合并。每一步仍用原 Stage-II 提示协议。
- 不把 H=2 或任意固定化学深度当作完成条件。物理上下文、显存和可续作计算窗口单独记账；资源截断不是化学失败，也不能拿截断状态冒充已完成端点。截断样本如何参与优化需在实施前冻结。
- 保存逐步原始输入、输出、token、行为 logprob、执行前后状态、GT 来源、模板证据及分项奖励；所有新数据、缓存和测试产物放 Ceph。
- 不承诺尚未测量的加速倍数；记录生成、CPU 执行、模板匹配、存储和优化各阶段时间。

## 怎样判断是否有效

主结果必须是相同公开主产物起点、相同评测条件下的完整端点命中率；不能用 teacher forcing、GT 后缀成功率、可执行率或训练 loss 替代。结构前体准确率和完整混合物准确率分开，R1/R2 购买库闭合率另报。

同时报告不同电子步长下的端点表现、首偏离位置、IMPORT/FLOW/STOP 错误、资源截断率、GT-only 更新比例、真正产生端点相对优势的组数、模板已支持/未知比例，以及时间与 token 成本。

软件验收须覆盖：所有后缀动作确实产生策略梯度；GT/工具响应正确 mask；不注入 GT 候选；反向模板方向正确；离子/芳香表达不被误改；重复 IMPORT/循环不刷奖；断点恢复保留行为版本与逐步原始 I/O。这些单元测试不是模型效果证据。未经用户明确要求不运行小样本 smoke/pilot 实验。
