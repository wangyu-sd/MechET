# 纯 Qwen 电子流 Agent：执行反馈、轨迹修复与端点驱动的自进化

状态：**设计提案，待评审；未实现、未训练、未证明增益。**

本 PR 只提交方案，不合并或替换 PR #82–84，不停止当前太极任务，不提交新的训练或评测。用户要求是先把纯 Qwen 的改造方案提交 PR，再讨论实现。

## 1. 目标与范围

继续做 product-only 逆合成：输入产物，模型通过逆向电子流构造前体，最终答案由执行器状态得到，而不是先生成反应物再补解释。

“纯 Qwen”指同一个已有模型负责 IMPORT、FLOW、FINISH 的全部决策和参数。不接 CRN/GNN，不增加 value model，不更换成 Direct 模型，也不等于必须换成更大的参数规模。“base”在此指后训练起点，是已训练的 Qwen 基座加匹配的 Stage-II adapter，不是重新从原生 Qwen 开始。

“自进化”分成两件不同的事：

- **单次推理内修复**：模型根据执行器的真实反馈调整动作，权重不变。
- **跨轮后训练**：收集训练集上的自主轨迹，用独立验证的端点回报更新模型，验证通过后才发布下一版。

反复重试、保存文件、loss 下降，都不能单独称为自进化有效。

## 3. 三种改法与选择

| 选择 | 优点 | 局限 |
|---|---|---|
| **完整 Qwen + 执行反馈 + 端点后训练（推荐）** | 复用现有权重与工具协议，模型拥有整条轨迹，移除混合分数瓶颈 | 仍需解决稀疏端点回报，收益必须实测 |
| 只加搜索，不更新权重 | 改动较小，能保留多条路径 | 主要增加推理成本，不能称为模型自进化 |
| 继续联合 Qwen/图模型 | 可以保留图模型局部预测优势 | 还需修候选覆盖、跨类型归一化和双模型训练，不满足本次纯 Qwen 方向 |

先做推荐方案的最小闭环，不增加新语言、复杂规划器、环境片段全集枚举或外部 teacher。

## 5. 单次推理如何工作

输入保持现有自然语言 v2 协议：产物、执行器当前 SMILES、当前临时原子/键 inventory、已接受动作的压缩历史。每步都提供同一种观察，不根据 GT 动作类型改变提示词。

同一个 Qwen 直接生成完整工具调用：

1. `import_fragments`：需要外部电子参与者时引入，允许与电子流穿插，不强制全部提前导入。
2. `apply_electron_flow`：模型生成完整逆向电子事件，执行器解析位置、应用电子流并生成新状态。
3. `finish_trace`：请求终止；端点只能从执行器状态提取，不能用另一段 reactants 文本覆盖。

保留既有工具参数、临时地址语义、电子事件和执行规则，不重新训练一种 DSL。训练和推理必须使用同一 system prompt、chat template、工具 schema、history 压缩方式、thinking 设置和 token/EOS 处理。

### 反馈和修复

非法 SMILES、无效位置、非法电子事件、状态循环或截断时：

- 拒绝的动作不改变化学状态。
- 恢复到该动作之前的完整快照，包括 state、next-map、imports、visited 和 accepted history；KV cache 不能带入另一条分支的内容。
- 将拒绝动作和公开错误类别作为反馈，Qwen 在同一状态重新生成。修复反馈只记录当前分支的失败，不混入其他分支的状态或位置标号。
- 相同状态下重复同一被拒动作不无限重试；达到预算后记录失败，保留原始输出。

第一版建议每个反应保留 2 条独立完整轨迹，每条最多 40 次工具尝试，其中每个状态最多 2 次修复尝试；导入总预算 32 份，单次生成上限 384 tokens。所有初始和修复尝试都计入总预算，不能通过修复无限加算力。这些是**拟议配置**，不是已测最优值。截断记为失败，不补写 EOS，也不静默增加限制。

这不是无限宽度的树搜索。原始 K=1 无修复作为控制；两个独立轨迹和有界修复分别记录预算，不能把增加算力的收益归因于权重更新。

### 推理时不能知道什么

执行器能发现程序/化学状态约束错误，但不能判定一个合法前体是否就是记录答案，也不能证明实验收率。合法但端点错误的路径不一定会触发报错。

因此，推理不使用 GT 端点、GT 片段、GT 下一步或“这一步与答案不一致”反馈。端点 miss 只能由训练私有评测器给回报，不能转换成推理提示词。合法的其他路线保留在候选输出中，不凭“不同于 GT”判化学错误。

## 6. 跨轮自进化如何训练

每轮冻结一个行为检查点，在训练集完整反应上采集自主轨迹，验证、更新、发布候选版本。发布后下一轮才用新权重采样。推理程序、执行规则和评分定义不得由 agent 自行修改。

### 6.1 采样与回报

同一产物采样 2 条独立完整轨迹。用于 RL 的两条都来自冻结行为策略的真实随机生成，而不是“一个贪心候选 + 一个随机候选”或强制 GT 候选。初版训练使用 temperature=1、top-p=1、无 top-k 截断；另行记录贪心控制，不把它混进 on-policy 梯度。

回报为：`R = 1` 当且仅当接受终止并命中冻结的结构端点，否则 `R = 0`。正式优化首先针对记录端点，不借模型自评、可执行率或相似度替代正例。二值奖励的局限明确保留：它不等于实验化学真相，也会漏掉部分合理替代路线。

验证器单独运行。训练 actor 接口只有产品与公开执行反馈，GT 只在评分/监督进程中存在。

### 6.2 完整 Qwen 的轨迹级更新

动作概率来自同一个 Qwen 的完整生成 token，包括工具名、参数、闭合符和实际 EOS。工具反馈、输入模板和被强制的 token 不计入 actor 概率；第一版不强制工具类型或 GT 参数。

设两条独立轨迹为 `tau_i`，对每条使用另一条的回报作 baseline：`A_i = R_i - R_other`。RL 损失为：

```text
L_RL = -(1/2) * sum_i A_i * sum_t log pi_theta(a_i,t | o_i,t)
```

同一轨迹内包括失败后生成的修复动作；模型要学习整条实际采样路径，而不只训练首步 IMPORT 或最后一个 FLOW。端点奖励给整条路径信用，但这本身不保证解决长程信用分配。

每个采样批次只做一次该批次的 on-policy actor 更新，不重复用旧采样冒充新策略样本。后续如果需要多步优化，必须显式引入行为概率与正确的 off-policy/裁剪处理。不能把此式称为 PPO，也不能直接套用有限候选池的 softmax。

同组全 0 或全 1 时，LOO actor advantage 为 0。日志分别统计混合回报组、RL 梯度步、回放步和 KL；不能把回放更新记成端点 RL 更新。

初版另用冻结起点在实际访问观察上的 token 分布作 KL 正则，以及单独的监督回放损失。日志报告所用分布、token mask 和权重；不得把 sampled-slate KL 写成全策略 KL，也不宣称这种访问状态上的约束控制了全部状态分布。

### 6.3 没有正例时如何处理

不伪造正奖励，不把 GT 加入 actor 抽样池。采用已有训练轨迹做**单独的监督回放**，维持 IMPORT/FLOW/FINISH 能力；GT 训练信号合法，但必须与自主 RL 的效果分开报告。

自主生成并独立重放成功的轨迹可进入成功回放池；失败和全部重试仍保留在原始日志中。失败→修复的学习记录只从真实公开报错及对应的后续生成形成。若用教师轨迹构造修复监督，必须从同一公开观察可执行地重放，并标记 teacher-assisted，不得混称自主修复成功。

短 horizon 可继续作为单独的过渡回放/curriculum 数据，但“最后一步命中”不得记为从产物开始的端点成功。完整端点回报始终单独核算。

### 6.4 版本发布

训练池只接收 train 反应。validation 用于固定协议下的版本比较，不写入修复/成功记忆；test 不参与调参、训练或经验库。

固定验证集比较旧版与新版的 product-start 端点命中、失败类型和成本。只有取得可重复的端点改进才晋升；无增益则保留旧版，保存候选权重、结果和原因。不设置未经验证的目标准确率，也不自动部署不断漂移的权重。

## 7. 数据、评测与成本边界

保持已冻结的反应级划分：FlowER 官方 257,171 train / 2,890 valid / 28,971 test；机制训练使用明确命名的严格可执行 universe 257,167 / 2,890 / 28,967，只少既有 4/0/4 上游损坏反应。不再做二次筛选。

验证覆盖全部 2,890 条；正式 test 保留 28,971 的分母，明确记录 4 条机制不支持项，并另列 28,967 条过程指标。不要称 128 条历史结果为完整 benchmark。除非用户明确要求，不提交 smoke、pilot 或小子集实验。

同一固定预算分别比较：原始 Qwen、加公开反馈修复但未更新权重的 Qwen、后训练版本。报告 K=1 与完整候选集合的命中，失败也留在分母里。

候选排序不看 GT：接受终止的轨迹优先，随后按所有实际生成 assistant token 的 mean NLL 排序，固定 tie-break；保存 summed log-probability、mean NLL、长度和修复次数。这个排序是既有风格的启发式，不是化学正确性 oracle。完整轨迹概率用于 RL，mean NLL 只用于排序，不能混用。

分别统计模型生成 tokens、工具次数、错误修复次数、LLM/执行器/等待耗时。两个完整轨迹加反馈可能提高成本，没有测量前不承诺比当前更快。复用现有批量推理接口，同一轮多个反应的下一动作可并行生成；不新增模型副本或把未申请的机器当成可用资源。

## 8. 最小实现落点与验证要求

本 PR 不实现下列模块，只确定边界：

1. 复用 `scripts/run_natural_language_value_search.py` 的纯 Qwen 提示词/工具调用与执行路径；新增独立 agent 模式，不覆盖历史 evaluator。
2. Agent runner：完整快照、有界报错修复、accepted-history 与 rejected-feedback 分离。
3. 轨迹采集器：真实行为策略概率、完整 raw 输入输出、两个独立反应级样本；不继承联合图模型候选打分。
4. Qwen 端点后训练器：轨迹级 LOO 更新、独立回放与 KL、轮次级权重冻结与导出。
5. 评测/发布：固定全量划分、gold-independent 排序、与原始策略配对比较、无增益不晋升。

实现前后需要的单元/静态检查（不是实验结果）：

- 同一当前状态下 IMPORT/FLOW/FINISH 提示词完全一致；压缩历史与已绑定 Stage-II contract 一致。
- Stage-II 实际权重、认证 manifest 和 tokenizer/模型 revision 一致；不允许自动回退 Stage-I。
- 未使用 CRN/GNN/value model；FLOW 参数来自 Qwen 原始生成。
- 拒绝动作后的快照/地址/inventory 与执行前一致，合法重复导入不被误禁。
- 两个候选无共享状态、跨分支 history 或 KV 污染；EOS 截断不可伪装成功。
- 全零回报组 actor 梯度为零；混合回报组的概率梯度方向正确；回放单独计数。
- 行为轨迹概率与 teacher-forced 概率对齐，包括失败尝试与修复动作。
- 改动私有 GT 端点或参考轨迹不会改变推理可见提示词/反馈。
- 已成功的非 GT 中间路径不因参考分叉被自动纠正；测试集不进入训练池。
- resume 保存模型、优化器、随机数、完整日志游标与行为版本；没有匹配完整结果不能发布。
