## RSI loop and controlled comparison

The frozen Agent chooses which current molecule/electron context to expand. Its baseline uses actor logprob, observed novelty/work and molecular size; the RSI arm adds a verified cross-task experience priority. An experience is harvested only from an actual **TRAIN stock-closed route**, binding source ID, actor SHA, stock SHA, executed program hash, product context and map-invariant FLOW bond-order delta signatures. No memorized reactant SMILES are replayed.

Explicit disjoint TRAIN and DEV target JSONL rows must provide `id`, `cohort`, `product_unmapped`, `stock`. Their target structures and IDs must differ from all 460 frozen EVAL targets. The current implementation does **not** provide such TRAIN/DEV route sets or fake their outcomes.

For each actor and stock catalogue independently:

1. Run `eval_agentic_rsi.py run --split TRAIN --targets-jsonl /absolute/train.jsonl --mode agent`. Only complete route reports become candidates.
2. Run `eval_agentic_rsi.py harvest --reports /absolute/train-runs/track/agent --candidate /absolute/candidate.json`.
3. Run matched real DEV `--mode agent` and `--mode agent_rsi --allow-candidate --memory /absolute/candidate.json` with the same model, seed, targets, stock and budgets.
4. Run `pair-dev --baseline /absolute/dev-baseline --candidate-runs /absolute/dev-rsi --pairs /absolute/pairs.jsonl`.
5. Run `promote --candidate /absolute/candidate.json --dev-pairs /absolute/pairs.jsonl --promoted /absolute/promoted.json --track mech31k --stock-sha VERIFIED_STOCK_SHA --min-dev-pairs 8`. It **fails closed** unless the pairs are genuine DEV real-executor reports, have positive net full-route wins and demonstrate at least one frontier action changed by memory.

On EVAL, `--mode agent_rsi --memory /absolute/promoted.json` loads only a checksum-verified, DEV-promoted bank. Three different stock catalogues require three different promoted files; `--memory /absolute/memory_directory` selects stock-specific `ursa_bbs_v1.json`, `buyables_publication.json`, `n5_publication.json`. Independent TRAIN/DEV promotion is required for each Stage-II model. Iterative RSI requires additional non-overlapping TRAIN attempts and promotion on permitted DEV, with frozen EVAL not recycled as training feedback.

**Scientific interpretation:** This is a concrete, nonparameterized experience-transfer policy with observable decision differences, not a reflection prompt. Its effectiveness is an **unproven hypothesis** until disjoint complete-route tasks improve under matching inference budgets. The 16-route set is only a feasibility pilot, not sufficient NMI statistical evidence. Keep older PUCT results as historical; they are not newly reproduced. Retain paper R1–R5 order, augment R1 with successful Agent route search and R4 only with verified self-improvement.
