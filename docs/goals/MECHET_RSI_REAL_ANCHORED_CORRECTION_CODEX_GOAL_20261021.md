### 1. Scientific and engineering decision

**Method name:** MechET-RSI v1: Real-data Anchored Round-trip Self-Improvement.
**Hypothesis:** Executable, train-only FlowER reaction demonstrations stabilize a Qwen reverse electron-flow policy while forward-checked, model-owned alternative disconnections supply new preferences. Repeated policy-generated preference refresh adds value beyond replay-only or static-D0 DPO.

The method remains PURE QWEN3-0.6B (State-SFT -> Trajectory-SFT -> RSI), with frozen original Forward F0 for R0/R1v1/R2v1 judgement. No CRN-JEPA, graph model/head, new backbone, model-generated direct precursor channel, MCTS inside the training loop or full SFT retraining. No text-only roundtrip label. Forward teacher-forced witness scoring may guide which candidates to CHECK but may not be counted as autonomous chemical success without independent calibration.

### 4. Correct preference construction and allocation (the primary coverage fix)

In src/mechet/roundtrip_reward.py, split:
- HARD_NEGATIVE: executor rejects at a true common prompt; formally demonstrated same-state cycle/no-op; task-incompatible terminal with a verified comparator;
- UNRESOLVED: valid executable reverse reaction with a single F0 forward mismatch, F0 nonterminal/censored, or never-forward-checked candidate; **do not silently count these as chemistry-negative labels**;
- SOFT_FORWARD_PREFERENCE (optional explicit ablation): F0 reconstructions with stronger independent evidence (e.g. repeated K_F>=2 outcomes or calibrated margin) versus lower-verified alternatives. Use lower bounded weights and report the source of each preference; never call soft negatives experimentally false.
- STRONG_PREFERENCE: two completions at the identical full Stage-II model-visible prompt, with distinct executed chemical successors, productive chosen, strong nonproductive/executor-invalid alternative, replay-verified action bytes and whole <|im_end|> completion. Never pair unrelated states or role-different tool prompts.
- REAL_DEMONSTRATION: train-only replayed FlowER authentic assistant tool call, **for SFT retention**, not universally assigned as DPO chosen against every alternate legal route. Optional GT-vs-invalid pair only when the model proposed a demonstrably rejected action from exactly the same prompt.

Replace **global high/low F0-score allocation** with a TARGET-/STATE-PAIRED scheduler:
1. Group autonomous reverse candidates by original product ID and exact common-state observation, distinguish chemical successors; do not count same successor multiple times.
2. Spend F0 checks in complementary pairs on the same product wherever possible; maximize informative chosen/rejected potential per F0 generated token, not raw F0 samples over disjoint targets.
3. Allocate initial reverse K2 per train target, expand K4/K8 only on products with plausible unmatched chemical options. Keep ALL attempted actions/costs; cap forward attempts (64 per 128-target cohort initially; log any expansion separately).
4. Sample by source reaction ID to avoid pseudo-replication. Set a **max pair contribution per source reaction** and count distinct chosen episodes. Report D0 and D1 by IMPORT, FLOW, FINISH and chemistry class; 20 IMPORT-only pairs are not evidence of a general electron-flow policy improvement.
5. The existing forward-witness score AUC ~0.588 is NOT a valid label source; retain calibration and optionally use it solely as a *sampling heuristic control* compared to randomized within-target paired allocation.

If newly corrected strong pairs remain scarce, still deliver complete audit and the replay-only control; do not force arbitrarily many DPO optimizer steps using weak labels.

### 5. Anchored DPO: mix authentic FlowER replay with independent round-trip preferences

Extend src/mechet/rsi_objective.py (do not replace it with a new RL framework).

**DPO term** stays exact full tool-call chosen-vs-rejected conditional log-probs at the same prompt, with fixed frozen original R0 reference, beta=0.1. Cache reference margins once by SHA and full action tokens. Maintain authentic per-action EOS and mask; never optimize executor/user tokens. R0 and F0 weights never update.

**Real-data retention term** is token-masked teacher-forced cross entropy on REAL, replay-verified Stage-II train source assistant tool calls, under their original matching current-state + compact-history prompt; label is the complete actual IMPORT/FLOW/FINISH tool-call, not an endpoint SMILES completion. The objective is:

  L = mean(DPO on independently weighted reaction groups) + lambda_replay * mean(Real-SFT action-only CE)

Initial smoke proposal: 3 preference microexamples and 1 distinct real-SFT replay microexample per 4 accumulated slots **only while enough distinct DPO pairs exist**. Also run ReplayOnly and corrected-DPO-only controls. Log the per-branch unweighted loss and gradient contribution (or measured separate grad norms) so the replay factor is an actual stabilizer, not nominal. Lambda is a versioned hyperparameter, starting at 0.25 for action-token-normalized CE, adjustable using a TRAIN-only calibration of gradient scale; do not tune it on VALID32 outcomes. Replay sampling should include local selected train source reactions and an independent diverse TRAIN-only reaction sample, not only the 9 D0 positive reactions, with stratification by tool type and chemistry class. A limited pool (e.g. 512 independent TRAIN reactions, 1–4 actions each) is enough for smoke; never ingest TEST.

**Cap overfitting:** Do not run exactly 50 steps regardless of data. Initial max 4 DPO exposures per UNIQUE pair and a max per-reaction contribution; optimizer step count derives from actual independent pair count and gradient accumulation. For a pool like v0's 11 pairs, 50x4=200 pair exposures is prohibited. Set a short, documented maximum (e.g. 20 optimizer steps per round, conditional on observed unique groups), and keep each update's unique-pair exposure count, replay-token ratio, behavior-policy KL, action-type entropy and a retention score. Retain candidate weight SHAs separately. Training loss decreasing on repeated 11 labels is not independent evidence.

For data-efficiency attribution, compare **equal train token/update budgets**:
- M0: untouched R0 frozen;
- M1: R0 + Real-SFT replay only;
- M2: R0 + corrected Cycle-DPO only;
- M3: R0 + corrected Cycle-DPO + Real-SFT replay (PRIMARY).
If M3 is better, refresh using M3 to produce a genuinely NEW D1v1 and R2v1 (same anchored objective). Add static-D0 second-round control when viable; R1v0 and R2v0 are retained historical diagnostics, not silently used as parents for v1.

### 6. Fix failure feedback and fair comparison without conflating it with training improvement

- Never silently mark rejected proposals as accepted, and do not allow unbounded retries.
- Evaluation tables must compare R0 and revised agents BOTH with fix disabled, and separately show a BOTH-with-fix-enabled inference ablation. Otherwise runtime improvements would be mislabeled policy gains.
