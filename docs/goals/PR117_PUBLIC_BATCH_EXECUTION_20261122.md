# Batched execution for the complete Reference benchmark

The public Reference benchmark retains all 1,084 official targets, source stocks, target order metadata and seeds. The operational plan assigns them to eight disjoint execution batches in round-robin order. Four batches contain 136 targets and four contain 135. Each contains 75 linear and 50 convergent cases, with ten or eleven long-route cases. The batches belong to one final full-population evaluation under the confirmed method, actor and common call cap.

At a 64-call ceiling the whole evaluation allows 69,376 calls. The largest batch allows 8,704. The observed earlier A100 throughput translates to approximately 81.2 device hours overall or up to 10.2 per batch. These are maximum-budget projections. Each count and duration in the final report comes from the actual batch receipts. The registered method gate and the Nov 29–Dec 03 planned execution window still apply. ## Execution and recovery

- Build the public registration with `scripts.pr117_public_registration` using `--confirmation-launch`, `--confirmation-evidence` and `--confirmation-evidence-sha256`. Use the completed finalizer `evidence.json` from the registered 96-target comparison. The registrar binds the exact target and arm identities and authenticates the independently replayed physical calls. If selecting trained weights, provide the durable checkpoint and its digest together with `--paired-actor-evidence` and `--paired-actor-evidence-sha256` for the completed `paired_actor_results.json`. The registrar verifies that this exact checkpoint and controller produced the paired results for all 96 targets. Use the frozen `reference_public_batches_1084_20261122/batch_plan.json` from the shared run. The batch launcher authenticates the complete original panel, method, stocks, actor and schedule before selecting work.
- Use `python -m scripts.pr117_public_batches validate` with the public registration and plan digests. The `run` mode accepts a batch index and a legitimate separate GPU allocation receipt. It writes a dedicated batch directory, and an existing directory prevents a second execution. Completed batches stay available after interruption. The other untouched batches remain eligible for execution, with the original target budgets and seeds.
- Use the `merge` mode with the same digests and archived native receipt audit on `PYTHONPATH`. It independently replays each published target result against the matched actor and full policy, including targets inside a batch without a final summary. It reports replayed target outcomes and all observed dispatches separately. Whole-population, route-cohort and training-exposure scores require a verified target outcome for all 1,084 identities and a matching summary from each batch. The training-exposure groups are exact matches, connectivity-only matches after relaxing stereochemistry, and targets with no connectivity match in the indexed training sources. The separate independent summary also excludes reused development targets. The official denominator remains 1,084. The exposure annotations are evaluator-only.

The CPU input audit reconstructed the original full 1,084 target rows exactly. The merge was exercised with 24 authentic archived development cases and 720 native calls. Presenting 16 of those outcomes yielded a partial report with the full registered denominator. These checks exercise the input and reporting paths before public generation.
