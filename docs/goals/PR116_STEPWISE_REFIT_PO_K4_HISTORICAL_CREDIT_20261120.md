# PR116 — Stepwise ReFIT-PO: K=4 electron candidates, historical path credit, and low-cost route RL

**Status: USER-SELECTED NEXT METHOD / IMPLEMENTATION HANDOFF (2026-11-20). DESIGN ONLY; NO NEW CODE, TRAINING OR METRICS ARE CLAIMED BY THIS FILE.**

This document adds the next ReFIT-PO research condition to PR116. It does not erase the 64-update teacher-free experiment or the stopped online FlowER run. The goal is **better online long-horizon retrosynthesis RL at dramatically lower sampling cost**, NOT another SFT project, an offline-DPO replacement, or a new template-driven agent.

## 1. Research decision and precise distinction from old G4

- **Old G4 = group size 4:** four *independent complete route rollouts per target*, plus separately sampled ReFIT electronic suffix branches. PR116 completed 64 updates / 2,048 TRAIN roots, and 512 final held-out targets; preserve all source evidence and labels.
- **New K4 = four candidate native tool actions at ONE exact decision state:** use one currently active route trajectory per root, draw four distinct *sampling receipts* from the same frozen Qwen behavior actor and same exact state/observation, execute/score the four options, stochastically choose ONE legal continuation, and retain the rest as alternative edges.
- The four samples can be batched at the GPU inference backend, but a batch of four generated actions is NOT a single neural prediction and is NOT four complete route rollouts. K=4 is a candidate-slate size, not a model optimizer microbatch or a separate independent-route group.
- Do not silently stack new K4 with the old four full-route samples or the old 2–16 full suffix forks. New condition: 32 root targets per optimizer update as the starting PR116 training stream; one primary route search per target, with explicit state restoration and optional saved alternatives.
- Preserve the current Qwen3.5-0.8B corrected History-89442 Stage-II initialization, native IMPORT / FLOW / FINISH interfaces, Executor, AND/OR stock closure, process reward and clipped policy optimization. New search controller/training estimator is a separate version, not an unlabelled reproduction of old Standard ReFIT-PO.
- No online FlowER teacher, RetroChimera teacher, mandatory LLM template expansion or new Stage-II SFT. CRN-JEPA PR18 is a **frozen, batched local ElectronEvent scorer**, with caching.

## 2. One state transition (the actual algorithm)

For each active exact decision state, identified by target, current mapped state, route/AND-obligation context, accepted tool history, prompt token IDs, tool/executor contract and behavior-policy version:

1. **Propose:** draw exactly K=4 independent native action receipts from the same actor checkpoint at the same prompt, using actual generated token IDs and behavior log-probabilities. Requests can be concurrently batched across states/GPUs.
2. **Execute locally:** parse all four proposals on four copies of the pre-decision Executor state. Use grounded semantic action identities to avoid repeated deterministic Executor calls for duplicate actions. Rejection is an observed failure of that proposal, not a failure of every other candidate.
3. **Score locally:** give a clear penalty to malformed/illegal/loop-forming/unproductive actions; give accepted actions a bounded, comparable local score. For precisely mappable FLOW ElectronEvents, optionally add a normalized CRN-JEPA PR18 *event-level support* score. It is not a calibrated full-reaction yield or a verified reaction-success probability. IMPORT and FINISH are scored by their native semantics, not coerced into ElectronEvent scores. Unknown/mismatched CRN-JEPA inputs are neutral/unavailable, never automatically invalid.
4. **Select:** among legal, distinct semantic choices use weighted random selection, e.g. q(i|s,C) = (1-epsilon) softmax(local_score_i/tau) + epsilon/N_legal. Save the full slate, local scores, sampled selection index and its exact probability. Do NOT always choose argmax: stochastic exploration is required.
5. **Advance one state:** only the selected action mutates the active search path. Keep the other valid candidates as saved alternatives for this exact decision snapshot; do not produce four full route suffixes.
6. **Backtrack on failure:** on a later deterministic execution failure or cycle, restore the nearest valid saved snapshot and sample from its untried legal alternatives. Do not regenerate the accepted prefix and do not repeat a previously known rejected edge. Distinguish within-reaction cycles from route-ancestry cycles. If all alternatives are exhausted, backtrack further or mark this search as failed. Resource/budget censoring stays unknown, not negative chemistry.
7. **FINISH and termination:** a valid FINISH completes one executable reaction, adds ALL precursor obligations to the existing AND/OR route network and continues if any precursor remains outside stock. The root is successful only when **the whole AND/OR route tree** is executable, acyclic and all required leaves are in the authentic inventory; a single precursor reaching stock is not success. Save route certificate and the causally contributing ELECTRON action history.
8. **Stop/reuse:** if the root has a successful stock-closed route, register its complete route certificate and stop first-solution collection for that target if the frozen condition requests one solution. Keep alternative route collection separately identifiable. Content-address and reuse verified deterministic execution, completed reaction programs and previously explored failures when their state/context contracts really match.

## 3. Two-tier reinforcement learning: local four-way comparison + real long-horizon credit

**Tier A — local candidate-level GRPO.** At each visited state there are four *real* actor samples. Calculate an immediate local score for each (Executor legality, cycle/duplicate semantics and optional PR18 support), and a group-relative advantage for the four candidates. Train using each candidate's true native tokens and behavior log-probability. A repeated semantic action must not get extra independent *chemical* evidence or dominate the unique-action baseline merely by being sampled again. Store all four receipts, including locally invalid actions.

**Tier B — genuine route-level ReFIT credit.** On full root stock closure, traverse the actual selected electronic path(s) in the complete AND/OR certificate and register the observed success and process rewards. On a real failure, register its path, exact failure cause and actual visited decisions. Compare this new success with **previously observed unsuccessful continuations from the same exact decision context**, and with any alternate branch that has itself truly been tried. The comparisons are historical observed outcomes, never imaginary long-horizon outcomes for unselected candidates. Unchosen and never-expanded candidates have known local evidence only; their long-term outcome remains UNKNOWN.

A successful route's terminal reward must **NOT** be copied as the long-horizon reward of all four candidates (especially not to illegal/untried ones). Nor may one old failed rollout be relabelled as a fresh on-policy sample from a new actor. Historical failed branches guide selection and form explicitly labelled conditional comparison evidence; if an optimizer trains on previous-policy receipts, it must use an explicit off-policy objective/correction rather than silently mixing them into the current on-policy GRPO group.

**Important selection-bias contract:** the route is sampled by a **compound procedure** (four policy draws followed by a score-conditioned selection), not by raw Qwen pi alone. Merely treating the chosen action as an ordinary pi rollout is not an exact on-policy route gradient. Record the true K candidate log-probabilities, selection probabilities and policy version. For exact on-policy route-level policy gradient, implement the likelihood of the **sampled slate plus selected index** (joint log probability: sum of actual four policy draw log-probabilities plus selection log-probability, if selection depends on trainable policy parameters). Use a proper trajectory baseline and the existing clipping/KL machinery adapted to this joint sampling policy; document per-token/shared-prefix weighting and whether the selector is frozen or differentiable. A chosen-action-only route update is an optional approximation/control, not the exact GRPO baseline. Tier-A local score objective and Tier-B terminal route objective must be logged separately and weighted once, with no duplicated reward on one receipt.

The scientific goal stays the same: improve electronic actions for **long-horizon synthesis planning**, not just make PR18 scores larger. Tier-A gives inexpensive immediate comparisons; Tier-B propagates authentic downstream route success/failure and exact-state history to electronic decisions. Preserve the original Standard ReFIT-PO loss/results as an independent comparator.

## 4. Historical state/action/result memory and compute savings

Store a journalled decision-node record containing: target/route occurrence and exact conditioning SHA; immutable pre-action Executor snapshot; four candidate native tokens and log-probabilities; action semantic keys; deterministic execution outcomes; optional frozen PR18 score and scorer SHA; selection probability and index; alternative-edge visited/unknown/failed/closed status; policy version; and any final AND-route certificate and observed return.

Maintain three distinct caches:
- **Deterministic execution cache:** same exact state/action/tool+executor contract -> same Executor transition or deterministic rejection. Reuse without pretending a new policy sample occurred.
- **Search graph/history cache:** same exact route context can reuse already observed success/failure and untried alternatives, preventing cycles and repeat subtree expansion. Different route obligations may require distinct search contexts even for identical molecular SMILES.
- **Policy training receipts:** original native sampled tokens, prompts, log-probs and actor SHA remain separate from cached chemistry outcomes. Never fabricate a new stochastic suffix or a new behavior receipt from a cached result.

If the original route visits A -> B -> C and fails at D, resume from a saved legal alternative near D, retaining A/B/C and their evidence. Every backtrack preserves the actual path and records whether a branch was fully observed or simply censored. Do not give negative chemical credit to unexpanded or resource-censored branches.

Reuse PR112 components where actually available: route_execution_cache, route_work_broker, route_global_sampler, route_distributed_collection, route_vllm_backend/cache, native receipt journalling and the existing ReFIT/AND-route components. No second independent cache framework or second full search engine.

## 6. Required tests and research receipts

**Algorithm:** four receipts share the exact observation; distinct native tokens/log-probs; same-state semantic dedup; invalid local candidate not selectable; no finite valid candidate triggers backtracking/termination; weighted selection probability sums to one; stochastic seeded replay; CRN missing/unknown never turns legal event illegal; import/finish remain typed; original G4 mode unchanged.

**Chemical/route:** no stale bond references after restoring a snapshot; replay outcome identical; a valid FINISH alone is not root success; convergent AND closure only after *all* terminal precursors reach stock; detect route-ancestry and within-reaction loops without falsely closing route; successful route certificate backtraces the actual selected actions; failed/unknown and old-policy historical paths are labelled distinctly.

**Learning:** four local candidate rewards are independent from route terminal outcomes; success reward not duplicated as if all four actions led to success; identical action duplicates cannot supply fake independent Q; exact joint-sampling/selection probability and ratio accounting checked with a small enumerated toy; current-policy vs prior-policy receipts separate; full policy loss/gradient finite, resume consistent. If exact joint-route gradient is not implemented, label the route update as an approximation and do not claim exact on-policy equivalence.

**Performance:** completed original policy decisions, candidate samples, accepted/unique actions, repeated candidates, executor replay/cache hits, CRN scorer calls and coverage, actual GPU memory/wall time, GPU requests per solved target, local GRPO informative groups, completed route credit, successful recovery from earlier failures, route cycles, rejected calls, target-level inventory closure, reference-supported routes, and independent chemistry evidence. Compare against the existing saved Stage-II and PR116 Standard ReFIT-64 without modifying their outputs; report new model's actual compute separately. Do not claim savings based solely on counting a batch of four as one neural request.
